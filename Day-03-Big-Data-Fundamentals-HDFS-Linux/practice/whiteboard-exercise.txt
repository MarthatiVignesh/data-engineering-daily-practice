WHY DISTRIBUTED SYSTEMS?
------------------------

Big Data
   |
   v
Single Machine
   |
   +-- Limited storage
   +-- Limited processing power
   +-- Limited scalability
   +-- Single point of failure
   |
   v
Distributed System
   |
   +-- Multiple machines
   +-- Shared storage
   +-- Parallel processing
   +-- Horizontal scalability
   +-- Fault tolerance

GFS
---

GFS stands for Google File System.

It demonstrated how large files could be stored across
multiple machines in a distributed environment.

GFS influenced the design ideas behind distributed
file systems such as HDFS.


MAPREDUCE
---------

MapReduce is a distributed processing model.

Input Data
     |
     v
   MAP
     |
     v
Intermediate Results
     |
     v
  REDUCE
     |
     v
 Final Result


Example:

Input:
A A B B A

MAP:
A -> 1
A -> 1
B -> 1
B -> 1
A -> 1

REDUCE:
A -> 3
B -> 2


HADOOP 1.0
----------

Hadoop 1.0 mainly consisted of:

        +----------------+
        |      HDFS      |
        +----------------+
                +
        +----------------+
        |   MapReduce    |
        +----------------+

MapReduce handled both resource management
and job processing.


HADOOP 2.0
----------

Hadoop 2.0 introduced YARN.

        +----------------+
        |      YARN      |
        | Resource Mgmt  |
        +----------------+
                |
        +-------+-------+
        |       |       |
      Jobs    Apps   Frameworks

HDFS continued to provide distributed storage.

YARN separated resource management from
processing.


YARN
----

YARN stands for Yet Another Resource Negotiator.

Main purpose:

- Manage cluster resources
- Allocate resources to applications
- Schedule application execution
- Allow multiple processing frameworks

KEY COMPARISON
--------------

Hadoop 1.0:

- HDFS for storage
- MapReduce for processing
- JobTracker managed jobs/resources
- TaskTrackers executed tasks

Hadoop 2.0:

- HDFS for storage
- YARN for resource management
- Multiple processing frameworks
- Better scalability and flexibility
